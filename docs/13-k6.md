# K6 - Tests de Performance

## 1. Presentation

- **Role** : Tests de charge et de performance, valide la tenue en charge avant prod
- **Outil** : K6 (Grafana Labs), open source, performant
- **Pas de port expose** (CLI uniquement, execute dans le pipeline)
- **Execute en PREPROD uniquement** (DEV non fiable, PROD impacterait les utilisateurs)
- **Job Jenkins autonome et planifie** (`Jenkinsfile.k6` + `k6Pipeline.groovy`),
  **pas un stage du pipeline de build** : un test de charge n'a de sens qu'en
  tendance, et il ne depend pas du workspace du build
- **Planification par defaut** : `H 2 * * 1` (tous les lundis vers 02:00),
  surchargeable ; declenchable a la main via "Build with Parameters"
- **Scripts en JavaScript** versionnables avec le code source
- **Profil de charge par defaut de la shared library** : 50 VUs pendant 3 min,
  script `tests/performance/load-test.js`
- **Seuils** : p95 < 500ms, taux erreur < 1%
- **Resultats exportables** vers Prometheus / Grafana pour visualisation

### Architecture

```
Job Jenkins planifie "<projet>-k6"  (cron H 2 * * 1)
+----------------------------------------------------+
|                                                    |
|  cible : PREPROD deja deploye (independant du build)|
|                          |                         |
|                  +-------+-------+                 |
|                  | 50 VUs        |  (parametrable  |
|                  | duree 3 min   |   par run)      |
|                  +-------+-------+                 |
|                          |                         |
|              Verification des seuils :             |
|              - p95 latency < 500 ms                |
|              - error rate < 1%                     |
|                          |                         |
|          k6-summary.json -> archive Jenkins        |
+----------------------------------------------------+
```

K6 simule N utilisateurs virtuels qui executent des scenarios HTTP. Si les seuils definis (thresholds) sont depasses, K6 retourne un exit code non-zero -> Jenkins marque le pipeline en echec et bloque la promotion vers PROD.

## 2. Configuration

### Execution dans le pipeline

K6 est execute via `docker run grafana/k6`, dans un job Jenkins autonome et planifie (`Jenkinsfile.k6`, cron hebdo), independant du pipeline de build/deploiement. Le script de test est dans `k6/load-test.js` du depot du projet. Voir `infrastructure/jenkins/shared-library/vars/k6Pipeline.groovy` et le modele `infrastructure/jenkins-pipelines/Jenkinsfile.k6`.

### Script de test type (`k6/load-test.js`)

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 100,                  // 100 utilisateurs simultanes
  duration: '5m',            // Pendant 5 minutes
  thresholds: {
    http_req_duration: ['p(95)<500'],   // 95% des requetes < 500ms
    http_req_failed:   ['rate<0.01'],   // < 1% d'erreurs
  },
};

export default function () {
  const res = http.get('https://thetiptop-preprod.wk-archi-o24a-4-5-g1.fr/');
  check(res, {
    'status is 200': (r) => r.status === 200,
    'duration < 500ms': (r) => r.timings.duration < 500,
  });
  sleep(1);
}
```

### Commandes type

| Commande | Description |
|----------|-------------|
| `k6 run script.js` | Execution simple |
| `k6 run --vus 100 --duration 5m script.js` | Override VUs et duree |
| `k6 run --out json=result.json script.js` | Export JSON |
| `k6 run --out experimental-prometheus-rw script.js` | Export Prometheus |

### Seuils par defaut Furious Ducks

| Metrique | Seuil | Justification |
|----------|-------|---------------|
| `http_req_duration p95` | < 500 ms | UX acceptable sous charge |
| `http_req_failed rate` | < 1% | Tolerance erreur basse |
| `vus` | 50 (defaut `k6Pipeline`) | Charge representative sans saturer l'agent |
| `duration` | 3m (defaut `k6Pipeline`) | Duree representative |

Ces deux valeurs sont surchargeables par projet dans le `Jenkinsfile.k6`
(`k6Vus`, `k6Duration`) et par execution via les parametres de build.

## 3. Mise en route

K6 ne necessite **aucune installation manuelle** : il est execute via `docker run` dans Jenkins.

### 3.1 Prerequis

- Docker disponible sur les agents Jenkins (deja le cas).
- Environnement PREPROD deployed et accessible (URL en HTTPS via Traefik).
- Script k6 present dans le depot du projet. Chemin par defaut :
  `tests/performance/load-test.js` (surchargeable via `k6Script`).
- Job Pipeline (**pas** multibranch) cree dans Jenkins sur la branche `main`
  avec Script Path `Jenkinsfile.k6`, lance une fois a la main pour que Jenkins
  enregistre le cron et les parametres.

### 3.2 Pre-pull de l'image K6

```bash
docker pull grafana/k6:latest
```

### 3.3 Creer le premier script de test

Dans le depot du projet :

```bash
mkdir -p k6
cat > k6/load-test.js <<'EOF'
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 10,           // Demarrer petit pour validation
  duration: '30s',
  thresholds: {
    http_req_duration: ['p(95)<500'],
    http_req_failed:   ['rate<0.01'],
  },
};

export default function () {
  const res = http.get(__ENV.TARGET_URL || 'https://thetiptop-preprod.wk-archi-o24a-4-5-g1.fr/');
  check(res, { 'status 200': (r) => r.status === 200 });
  sleep(1);
}
EOF

git add k6/load-test.js
git commit -m "test: add k6 load test script"
git push
```

### 3.4 Premier test en local

```bash
cd /chemin/vers/projet

docker run --rm -i \
  -v $(pwd)/k6:/scripts \
  grafana/k6 run /scripts/load-test.js
```

Sortie attendue : statistiques de requetes, verification des seuils.

### 3.5 Verifier l'integration dans le Jenkinsfile

```bash
sed -n '1,60p' \
  /opt/furious-ducks/infrastructure/jenkins/shared-library/vars/k6Pipeline.groovy
cat /opt/furious-ducks/infrastructure/jenkins-pipelines/Jenkinsfile.k6
```

### 3.6 Augmenter progressivement la charge

Une fois le script valide a 10 VUs, monter la charge. Le profil effectif est
impose par le job (`--vus` / `--duration` passes par `k6Pipeline`), donc c'est
le `Jenkinsfile.k6` qu'il faut ajuster, pas seulement le script :

```groovy
k6Pipeline(
    // ...
    k6Vus      : 100,
    k6Duration : '5m',
)
```

### 3.7 Configurer l'export vers Grafana (optionnel)

Pour visualiser les resultats K6 en live dans Grafana :

```bash
docker run --rm \
  -v $(pwd)/k6:/scripts \
  -e K6_PROMETHEUS_RW_SERVER_URL=http://common-prometheus-ci:9090/api/v1/write \
  grafana/k6 run \
    --out experimental-prometheus-rw \
    /scripts/load-test.js
```

Importer le dashboard officiel K6 dans Grafana (ID `2587`).

## 4. Utilisation au quotidien

### 4.1 Lancer un test de charge en local

```bash
docker run --rm -i -v $(pwd)/k6:/scripts \
  grafana/k6 run /scripts/load-test.js
```

### 4.2 Override les parametres en CLI

```bash
docker run --rm -v $(pwd)/k6:/scripts \
  grafana/k6 run \
    --vus 200 \
    --duration 10m \
    /scripts/load-test.js
```

### 4.3 Tester un endpoint specifique avec une variable d'env

```bash
docker run --rm \
  -v $(pwd)/k6:/scripts \
  -e TARGET_URL=https://thetiptop-preprod.wk-archi-o24a-4-5-g1.fr/api/concours \
  grafana/k6 run /scripts/load-test.js
```

### 4.4 Generer un rapport JSON pour analyse

```bash
docker run --rm \
  -v $(pwd)/k6:/scripts \
  grafana/k6 run \
    --out json=/scripts/result.json \
    /scripts/load-test.js

# Analyser le resultat
jq '.metrics.http_req_duration' k6/result.json
```

### 4.5 Tester un scenario plus complexe (login + parcours)

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = { vus: 50, duration: '5m' };

export default function () {
  // 1. Login
  let res = http.post('https://thetiptop-preprod.wk-archi-o24a-4-5-g1.fr/api/login', {
    email: 'test@example.com',
    password: 'test123',
  });
  check(res, { 'login OK': (r) => r.status === 200 });
  const token = res.json('token');

  // 2. Tirage
  res = http.post(
    'https://thetiptop-preprod.wk-archi-o24a-4-5-g1.fr/api/tirage',
    { code: 'XXXX-YYYY' },
    { headers: { Authorization: `Bearer ${token}` } }
  );
  check(res, { 'tirage OK': (r) => r.status === 200 });

  sleep(1);
}
```

### 4.6 Comparer les performances entre 2 versions

1. Run K6 sur la version `v1.2.0` -> sauvegarder `result-v1.2.0.json`
2. Deployer `v1.3.0`
3. Run K6 -> sauvegarder `result-v1.3.0.json`
4. Comparer :

```bash
jq '.metrics.http_req_duration.values."p(95)"' result-v1.2.0.json
jq '.metrics.http_req_duration.values."p(95)"' result-v1.3.0.json
```

### 4.7 Visualiser les resultats dans Grafana (live)

Voir section 3.7. Avec l'export Prometheus RW, les metriques sont visibles en temps reel dans le dashboard K6 Grafana.

## 5. Tests de validation

### Test basique

```bash
docker run --rm -i grafana/k6 run - <<EOF
import http from 'k6/http';
export const options = { vus: 1, duration: '10s' };
export default function () { http.get('https://www.google.com'); }
EOF
```

### Test avec seuils

Voir le script `k6/load-test.js` ci-dessus avec `thresholds`. Verifier que K6 :
- Retourne exit code `0` si tous les seuils sont OK
- Retourne exit code `99` si un seuil est depasse

### Verifier dans Jenkins

1. Jenkins -> job **`<projet>-k6`** (job Pipeline dedie, pas le job de build)
2. Lancer via **Build with Parameters** (ou attendre le cron du lundi)
3. Logs : verifier le resume final (passes / fails)
4. Build Artifacts : **`k6-summary.json`**

### Verifier la metrique exportee dans Prometheus

```promql
k6_http_req_duration_seconds
```

(Disponible si export Prometheus configure.)

## 6. Depannage

| Symptome | Cause | Solution |
|----------|-------|----------|
| Tous les seuils echouent | URL inaccessible | Verifier `curl -I https://thetiptop-preprod...` |
| Erreurs SSL/TLS | Cert invalide en preprod | Verifier Traefik + Let's Encrypt sur PREPROD |
| `connection refused` | Service down | Verifier `docker ps` du conteneur projet |
| K6 OOM (Out Of Memory) | Trop de VUs sur agent Jenkins | Reduire VUs ou utiliser un agent dedie |
| p95 toujours > seuil | Backend sous-dimensionne | Profiler l'application, optimiser, scaler |
| Faux positifs ponctuels | Ramping initial trop brutal | Utiliser `stages` au lieu de `vus` constant |
| Export Prometheus echoue | URL Prometheus incorrecte | Verifier `K6_PROMETHEUS_RW_SERVER_URL` |
| `script error: ...` | Erreur JS dans script | `docker run grafana/k6 run --paused script.js` pour debug |
